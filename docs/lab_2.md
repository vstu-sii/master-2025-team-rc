## Лабораторная 2

### Функциональные и нефункциональные требования.

#### 1. Функциональные требования:

#### 1.1. Требования к экзоскелету:

ФТ-1. Экзоскелет должен обеспечивать движение в тазобедренных суставах с помощью электромеханических приводов.

ФТ-2. Система должна работать в двух режимах:

ФТ-2.1. Режим "Усиление" - помощь пользователю при движениях

ФТ-2.2. Режим "Нагрузка" - создание дозированного сопротивления

ФТ-3. Система должна собирать и передавать следующие данные в реальном времени:
- Напряжение аккумуляторной батареи
- Углы поворота моторов в суставах
- Данные с датчиков (акселерометр, гироскоп)

ФТ-4. Система должна определять тип движения пользователя (ходьба, бег) с точностью не менее 80%.

ФТ-5. Экзоскелет должен автоматически адаптировать параметры управления на основе персональных данных пользователя.

#### 1.2. Требования к мобильному приложению:

ФТ-6. Приложение должно предоставлять интерфейс для:
- Выбора режима работы ("Усиление"/"Нагрузка")
- Ввода персональных параметров пользователя (рост, вес, длина бедра/голени)
- Установки уровня усиления/нагрузки (1-10)

ФТ-7. Приложение должно отображать в реальном времени:
- Текущий режим работы
- Уровень заряда батареи
- Определенный тип движения
- Статус соединения с экзоскелетом и сервером

ФТ-8. Приложение должно сохранять историю сеансов использования.

ФТ-9. Приложение должно принимать и хранить данные с экзоскелета.

#### 1.3. Требования к серверной части:

ФТ-10. Сервер должен принимать и хранить данные с мобильных приложений.

ФТ-11. Сервер должен обеспечивать хранение:
- Персональных параметров пользователей
- Данных о сеансах использования
- Статистики использования

ФТ-12. Сервер должен предоставлять REST API для обмена данными с мобильным приложением.

#### 1.4. Требования к системе машинного обучения:

ФТ-13. Модель ML должна классифицировать типы движений на основе данных с датчиков.

ФТ-14. Система должна обновлять ML-модель на основе накопленных данных.

#### 2. Нефункциональные требования:

#### 2.1. Требования к производительности:

НТ-1. Задержка в определении типа движения не должна превышать 100 мс.

НТ-2. Частота опроса датчиков должна быть не менее 100 Гц.

НТ-3. Время отклика системы на изменение режима - не более 1 секунды.

НТ-4. Точность определения углов суставов - ±1 градус.

#### 2.2. Требования к надежности и безопасности:

НТ-5. Время непрерывной работы экзоскелета - не менее 3 часов.

НТ-6. Система должна обеспечивать аварийную остановку при:
- Снижении напряжения АКБ ниже критического уровня
- Обрыве связи с приложением более 5 секунд
- Обнаружении аномальных значений с датчиков

НТ-7. Механическая прочность конструкции должна выдерживать нагрузку до 100? кг.

НТ-8. Защита от перегрева приводов.

#### 2.3. Требования к удобству использования:

НТ-9. Время первоначальной настройки под пользователя - не более 10 минут.

НТ-10. Мобильное приложение должно иметь интуитивно понятный интерфейс.

НТ-11. Процесс подключения к экзоскелету должен занимать не более 30 секунд.

#### 2.4. Требования к совместимости:

НТ-12. Мобильное приложение должно работать на Android 9.0+ и iOS 13.0+.

НТ-13. Связь с экзоскелетом по Bluetooth 5.0+.

НТ-14. REST API сервера должно поддерживать JSON-формат данных.

#### 2.5. Технические требования:

НТ-15. Вес экзоскелета без аккумулятора - не более 8 кг.

НТ-16. Уровень шума приводов - не более 45 дБ.

НТ-17. Диапазон рабочих температур: +5°C до +35°C.

## Архитектура системы.

Описание архитектуры системы.

Экзоскелет состоит из приводов (мотор, плата контроллера, акселерометр + гироскоп) и микрокомпьютера Raspberry. 

Приводы осуществляют передачу данных и прием команд от микрокомпьютера с помощью CAN-шины.

На микрокомпьютере осуществляется обработка полученных данных от приводов, обработка и отправка на клиентское приложение. Также на микро ПК работает модель машинного обучения, которая распознает тип движения на основе полученных от приводов данных.

В клиентском приложении производится управление параметрами работы экзоскелета. Также в нем имеется локальная база данных для хранения собранной с приводов информации и дальнейшей передачи их на сервер. Экзоскелет и клиентское приложение взаимодействуют с помощью Bluetooth. Приложение подключено к серверу через интернет посредством своего API.

Сервер имеет свою основную базу данных. На сервере расположен веб интерфейс администратора для удаленного взаимодействия с экзоскелетом, просмотра данных, а также отладки (изменения параметров работы экзоскелета), при необходимости.
